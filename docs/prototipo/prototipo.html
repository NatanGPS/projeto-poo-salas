Guia de Salas: Protótipo funcional (3ª etapa)

Natan Gaspar de Souza

Código-fonte, testes e dados estão no arquivo ZIP que acompanha este PDF. Para executar: python -m guia_salas. Para testar: python -m unittest discover -s tests -v (Python 3.10 ou superior, sem bibliotecas externas).

Etapa 1. Delimitação do incremento

1. Funcionalidades escolhidas

FuncionalidadeContribuição para o problema
F01: Buscar a sala de uma disciplina pelo nome ou códigoMostra o dia, horário, sala, prédio e andar de cada turma da disciplina. Foi a funcionalidade modelada na segunda entrega.
F02: Consultar salas livres num dia, hora, andar e prédioMostra as salas sem aula naquele horário, por exemplo para estudar entre duas aulas.

Fluxo de ponta a ponta. O aluno usa a F01 para descobrir que a aula de Introdução a Banco de Dados (turma TB) é na sala 2014 - DCC, no 2º andar do ICEx, segunda às 09:25. Em seguida, usa a F02 com esse dia, horário, andar e prédio para achar uma sala livre próxima. Dependências: as duas funcionalidades usam o mesmo catálogo, carregado uma vez a partir do quadro do ICEx. A F02 depende das aulas cadastradas para saber o que está ocupado, e os dados de entrada dela (dia, andar, prédio) são os que a F01 devolve.

Diferenças em relação à entrega anterior.

  • O ponto de entrada da demonstração é o MenuTerminal. O bot do Telegram continua no código, mas não faz parte deste recorte.
  • A fonte de dados foi dividida em uma hierarquia: FonteIcex (abstrata) concentra a conversão do JSON, e FonteIcexOnline e FonteIcexArquivo definem de onde o JSON vem.
  • A F02 foi implementada com validações próprias: prédio desconhecido (PredioDesconhecido) e andar negativo (DadoInvalido) são rejeitados pela ConsultaDeSalas; andar não numérico e hora inválida são rejeitados ao converter a entrada.
  • trocar_catalogo passou a validar antes de alterar: recusa um catálogo vazio e mantém o atual.
  • O modelo de domínio (Disciplina, Turma, Aula, Sala) e as regras R1 a R11 da segunda entrega não mudaram.

Etapa 2. Versão executável

4. Herança e polimorfismo

O quadro do ICEx é o mesmo JSON, mas o projeto precisa obtê-lo de duas formas: baixando do site (uso real, com dados atualizados) e lendo uma cópia local (demonstração sem internet, testes com dados conhecidos e servidor sem acesso ao site). A conversão do JSON em registros é igual nos dois casos, por isso fica na classe abstrata FonteIcex; cada subclasse implementa apenas _obter_json(). O AtualizadorDeBase chama fonte.coletar() sem saber qual classe concreta recebeu. Uma futura fonte da Escola de Engenharia entraria como outra subclasse de FonteDeDados, sem mudar o atualizador.

guia_salas/fontes/base.py
class FonteDeDados(ABC):
    """Fonte de registros de aulas."""

    @property
    @abstractmethod
    def nome(self) -> str:
        """Nome curto da fonte, usado para indicar a origem dos dados."""

    @abstractmethod
    def coletar(self) -> list[RegistroDeAula]:
        """Obtém os registros de aulas da fonte."""
guia_salas/fontes/icex.py
def coletar(self) -> list[RegistroDeAula]:
    """Obtém o JSON pela forma definida na subclasse e o converte em registros."""
    return self.interpretar(self._obter_json())

@abstractmethod
def _obter_json(self) -> dict | list:
    """Devolve o JSON do quadro do ICEx ou lança FonteIndisponivel."""

def _obter_json(self) -> dict | list:
    """Faz a requisição HTTP e devolve o JSON."""
    try:
        import requests
    except ImportError as erro:
        raise FonteIndisponivel("Instale a biblioteca requests para baixar os dados.") from erro
    sessao = self._sessao or requests.Session()
    try:
        resposta = sessao.get(self._url, timeout=self._tempo_limite,
                              headers={"User-Agent": "GuiaDeSalas/0.1"})
        resposta.raise_for_status()
        return resposta.json()
    except (requests.RequestException, ValueError) as erro:
        raise FonteIndisponivel(f"Falha ao consultar o ICEx: {erro}") from erro

def _obter_json(self) -> dict | list:
    """Lê e decodifica o arquivo."""
    try:
        return json.loads(self._caminho.read_text(encoding="utf-8"))
    except (OSError, ValueError) as erro:
        raise FonteIndisponivel(f"Falha ao ler {self._caminho}: {erro}") from erro

guia_salas/servicos/atualizador.py
def atualizar(self) -> tuple[CatalogoDeAulas, RelatorioDeAtualizacao]:
    """Coleta as fontes e devolve o catálogo consolidado com o relatório."""
    catalogo = CatalogoDeAulas()
    relatorio = RelatorioDeAtualizacao()
    for fonte in self._fontes:
        try:
            registros = fonte.coletar()
        except FonteIndisponivel as erro:
            relatorio.fontes_com_falha[fonte.nome] = str(erro)
            continue
        for registro in registros:
            relatorio.registros_lidos += 1
            try:
                relatorio.aulas_registradas += self.incluir(catalogo, registro)
            except ErroDeDominio as erro:
                relatorio.recusados.append((registro, str(erro)))
    return catalogo, relatorio

5. Estado e responsabilidades

  • Todos os atributos são privados por convenção (prefixo _) e lidos por propriedades somente leitura, por exemplo Sala.identificador, Sala.andar e Disciplina.turmas.
  • Não há setters para dados que vêm da fonte. Disciplinas, turmas, aulas e salas vêm do quadro do ICEx e só mudam por operações específicas: CatalogoDeAulas.registrar_aula, Disciplina.obter_turma e Turma.agendar_aula. Esta última verifica a regra R6 (aulas sobrepostas da mesma turma) antes de alterar.
  • ConsultaDeSalas.trocar_catalogo é o único ponto que troca o estado da consulta e recusa um catálogo vazio antes de alterar.
  • ConsultaDeSalas devolve objetos (ResultadoDaBusca, lista de Sala); o FormatadorDeRespostas transforma esses objetos em texto; o MenuTerminal apenas lê e imprime.
  • Classes, construtores, propriedades e métodos têm docstrings curtas que dizem o que cada um faz.
guia_salas/servicos/consulta.py
def trocar_catalogo(self, novo: CatalogoDeAulas) -> None:
    """Passa a responder com um catálogo recém-atualizado; recusa um catálogo vazio e mantém o atual."""
    if len(novo) == 0:
        raise DadoInvalido("O catálogo novo está vazio; a base atual foi mantida.")
    self._catalogo = novo

def salas_livres(self, dia: DiaSemana, instante: time, andar: int | None = None,
                 predio: str | None = None) -> list[Sala]:
    """Salas presenciais sem aula no dia e instante informados."""
    if andar is not None and andar < 0:
        raise DadoInvalido("O andar não pode ser negativo.")
    if predio:
        conhecidos = {p.casefold(): p for p in self._catalogo.predios}
        if predio.strip().casefold() not in conhecidos:
            raise PredioDesconhecido(
                f"Prédio \"{predio.strip()}\" não encontrado. Prédios na base: {', '.join(self._catalogo.predios)}."
            )
        predio = conhecidos[predio.strip().casefold()]
    return self._catalogo.salas_livres(dia, instante, andar, predio or None)

6. Execução pelo terminal

O comando python -m guia_salas carrega a amostra e abre um menu com as duas funcionalidades. Falhas de conversão (andar "dois", hora "25:00", dia "xyz") e rejeições de regra são mostradas como "Entrada recusada: ..." e o menu continua, sem alterar a base. Opções inexistentes geram "Opção inválida", e o fim da entrada (Ctrl+D) encerra o programa sem erro.

guia_salas/terminal.py
def consultar_salas_livres(self) -> None:
    """F02: pede dia, hora, andar e prédio e mostra as salas sem aula naquele instante."""
    try:
        dia = DiaSemana.de_texto(self._ler("Dia (seg, ter, qua, qui, sex, sab): "))
        instante = ler_hora(self._ler("Hora (HH:MM): "))
        andar = self._ler_andar(self._ler("Andar (vazio para todos): "))
        predio = self._ler(f"Prédio ({', '.join(self._consulta.catalogo.predios)}, vazio para todos): ").strip()
        salas = self._consulta.salas_livres(dia, instante, andar, predio or None)
    except ErroDeDominio as erro:
        self._escrever(f"Entrada recusada: {erro}")
        return
    self._escrever(self._formatador.salas_livres(salas, dia, instante, andar))

@staticmethod
def _ler_andar(texto: str) -> int | None:
    """Converte o andar digitado; vazio significa todos os andares."""
    texto = texto.strip()
    if not texto:
        return None
    try:
        return int(texto)
    except ValueError as erro:
        raise DadoInvalido(f"Andar inválido: \"{texto}\". Use um número, como 2.") from erro

Dados, persistência e limites desta versão

Os dados ficam apenas na memória, carregados da amostra a cada execução. Como as duas funcionalidades são consultas, nada é alterado, e nada se perde ao encerrar além da própria base carregada.

ItemRegistro
Dados a salvar e recuperarDisciplinas (código, nome), turmas (código), aulas (dia, início, fim, origem), salas (prédio, identificador, andar), data e hora da última atualização e os registros recusados de cada atualização.
Solução a investigarSQLite, pelo módulo sqlite3 da biblioteca padrão: um único arquivo, sem servidor, adequado ao servidor próprio previsto na proposta.
Fontes técnicas consultadasDocumentação oficial do Python, módulo sqlite3 (https://docs.python.org/3/library/sqlite3.html); SQLite, "Appropriate Uses For SQLite" (https://www.sqlite.org/whentouse.html).
DúvidaA cada atualização, substituir toda a base numa transação ou gravar só as diferenças, guardando histórico para avisar o aluno quando uma sala mudar?
Próximo experimentoCriar as tabelas disciplina, turma, aula e sala, gravar a amostra de 110 registros e comparar o tempo de abrir o programa lendo do SQLite com o tempo de baixar o JSON do ICEx.

Simulações identificadas. (1) No modo padrão, a cópia local do JSON (FonteIcexArquivo) substitui o download do site; o resultado é o mesmo formato de registros. (2) Nos testes, a SessaoFalsa substitui a conexão HTTP da FonteIcexOnline e devolve o JSON de teste. A regra central das duas funcionalidades (correspondência do termo e ocupação das salas) é sempre executada pelo código do projeto.
